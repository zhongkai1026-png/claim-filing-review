# 破产管理人债权申报与审查系统

面向破产管理人的本地债权申报与审查工具：上传申报材料 → AI 解析识别债权人信息 → 形成台账（登记/复核）→ AI 审查 → 人工复核 → 导出台账与审查意见书。

数据全部保存在本地（SQLite + 文件目录），不依赖外部服务即可运行核心流程。

## 功能

| 环节 | 说明 |
|------|------|
| 项目管理 | 每个破产案件建一个项目，债权数据按项目独立 |
| 上传申报材料 | 支持图片 / PDF / Word / txt，多文件批量；自动生成债权编号 PC-001… |
| AI 解析识别 | 文本型 PDF/Word 直接抽取；**扫描件 PDF 与图片优先走 MinerU 云端解析**（表格/公式还原更强，配置 `.env` 中 `MINERU_API_KEY` 生效，未配置或失败自动回退本地 RapidOCR）；字段识别预填台账（配置 LLM 后由 AI 结构化提取，否则规则引擎兜底），解析在后台异步执行 |
| 债权台账 | 25 项字段完整落地；点击债权人名称预览/下载原始材料；登记 / 复核状态流转 |
| 补充材料 | 台账操作列（及审查工作台）「📎 补充材料」：向已登记债权追加材料 → 与原有材料同库保存、在**同一材料预览页**一并查看（标注「补充」）→ 后台只解析新材料（扫描件走 OCR/MinerU）并同步提取信息到台账（**只补空、不覆盖**）→ **清空 AI 审查结论（回到未审查）**、人工复核标记未完成（原意见与审核金额保留），流程状态由「已复核」退回「已登记」，便于重新审查 |
| AI 审查 | 应用《破产债权审查操作指南》方法论：**7 级决策树逐级审查**（主体资格→时效→暂缓→生效文书→债权性质→金额核算→特别要件）+ **类型化审查**（借贷 LPR4 倍/购销违约金二分/工程款优先权 18 个月等按债权类型注入）+ **法律依据引用**；输出含 review_process（决策树过程）与 legal_basis（法条），并给出确认/暂缓/不予确认结论 |
| 人工复核 | 填写审核金额与审查意见，定稿后状态置为「已复核」 |
| 在线申报债权 | **公开申报网页**（`/apply.html?project=ID`）：债权人无需登录即可填写债权信息并上传材料；管理人点「在线申报 → 更新在线申报」一键导入台账（自动生成编号、材料入库、异步解析），**同名债权自动查重提示** |
| 数据后台 | 审查结论三组汇总（**已审查确认 / 暂缓确认 / 已否定**，各自含笔数、金额、本金/利息/其他，已确认组另附按债权性质明细）+ 四张构成图（申报金额构成、申报性质构成、已确认金额构成、已确认性质构成）+ 登记状态 + AI 审查结论；支持按债权性质筛选 |
| 导出 | 台账 Excel / CSV；**《破产债权审查结果通知书》** Word（公文格式：文号/申报情况表/审查结果表/四类结论勾选/差额说明/法律依据/权利告知/落款，单份或批量 zip） |

## 快速开始

```bash
cd backend
pip install -r requirements.txt

# （可选）配置 AI 审查：启动后在系统右上角点「⚙️ AI 设置」添加模型配置
# （支持任意 OpenAI 兼容接口：DeepSeek / 通义千问 / 智谱 / OpenAI 等，可添加多个随时切换）
# 不配置也能运行：AI 审查降级为内置规则引擎生成初步意见
python run.py
```

浏览器打开 http://127.0.0.1:8000

## 数据表

- `projects`：项目（名称、案号、债务人、管理人）
- `claims`：债权台账（25 项字段，含申报金额与审核金额、状态 pending/registered/reviewed）
- `claim_files`：申报材料文件（存储路径、解析文本；`origin=supplement` 标记补充材料）
- `audit_results`：AI 审查意见（JSON）与人工复核意见
- `online_claims`：在线申报（公开网页提交，待导入/已导入）
- `online_claim_files`：在线申报上传的材料文件
- `ai_configs`：AI 模型配置（系统内「AI 设置」管理，可添加/切换多个模型）

## AI 审查的提示词与方法论（提示词版本 v2-2026-09）

- **方法论来源**：《企业破产债权审查操作指南》（对应 `bankruptcy-claim-review` SKILL 的 ch01–ch04），摘编进 `backend/app/services/auditor.py` 的提示词常量。
- **提示词结构**：system ＝ 审查五要素 + 7 级决策树 + **通用审查规则 20 条** + 法律依据清单；user ＝ **类型化审查标准（11 类）** + 债权台账 JSON + 按文件分段的材料正文 + 输出 JSON 契约。
- **类型化标准 11 类**：民间借贷 / 买卖合同 / 金融 / 金融不良 / 建设工程 / 购房者 / 租赁 / 职工 / 税收 / 抵销 / 取回权（每类含 5–11 条编号要点，审查时按类型注入 1–2 类）。
- **类型判定优先级**：台账「债权类型」→「债权种类」（含同义词归一：金融债权→金融、工程债权→工程款…）→ 材料正文特征短语（仅在台账两列为空时兜底，抵销/取回权/金融不良可对台账口径做精化）。
- **可追溯字段**：审查结果记录 `prompt_version`（提示词版本）与 `injected_standards`（注入的标准），AI 输出新增 `standard_refs`（实际引用的条目编号，如 `["工程款-3"]`），审查工作台的 AI 面板会显示「提示词 v2-2026-09 · 标准：工程款 · 引用：工程款-2、工程款-3」，决策树各级 detail 末尾也带「（依据：工程款-3）」标注。
- **成本开关**：`.env` 中 `AI_PROMPT_PROFILE=full|basic`——`full`（默认）＝20 条规则＋11 类标准；`basic`＝核心 7 条规则且不注入类型标准（提示词从约 2,000 字符降到约 1,400，便于省 token 或出问题时回退）。
- **降级链**：未配置模型 → 规则引擎生成同结构意见（`ai_model=rule-engine`）；模型返回空/非 JSON → `ai_status=failed` 并把真实原因写入 `ai_error` 供前端展示。
- **案件信息注入**：审查提示词附带【案件信息】块（案号/债务人/管理人/**破产受理日**）；诉讼时效、执行期间、建设工程优先权 18 个月、撤销权期间、利息止息**一律以破产受理日为基准**。项目未填破产受理日时，模型会写明"无法判断，需管理人补充后重新审查"（不再臆造日期），台账与审查页同时显示橙色补填提示；审查记录保存当次注入的案件信息（`injected_case_info`）。
- **日期纪律**：材料中的年份不得被改写成当前年份；字段提取若出现该情况会按材料原值自动校正（例：材料写「2020年8月18日」而被输出成「2026年8月18日」→ 校正回 2020 年）。
- **解析状态与自愈**：`pending`→`parsing`→`done`/`failed`；Excel 导入台账（无材料）的行标记 `empty`（无材料无需解析）；解析中超过 30 分钟未完成（或服务重启导致任务中断）自动标记 `failed` 并写明原因；解析中重复点「重新解析」会被拒绝（409），避免重复清空文本与重复 OCR；台账操作列在解析中显示 ⏳、失败显示 ⚠（点 ⚠ 直接重新解析）。「重新解析」现在会在上方解析面板显示每份文件的进度。

## 数据后台口径说明

- **审查结论三组**：已审查确认（confirmed）/ 暂缓确认（partial）/ 已否定（rejected）。判定优先级为**人工复核结论**（认可 / 部分认可 / 不认可）→ 无人工结论时取 **AI 审查结论**（review_result）；两者都没有的计入「尚未出审查结论」，不计入三组。
- **金额口径**：该笔已录审核金额（`audited_*`）则取审核金额，否则取申报金额；鼠标悬停「笔数 · 金额」可看到该组的申报金额与审核金额原始值。
- **债权性质口径**：申报侧按申报性质 `claim_nature` 归类；已定论侧（三组明细）优先取人工复核确认的性质 `debt_nature`（仅当它能归入标准 7 类时），否则回退申报性质。无法归入 7 类的计入「未标注」——若「未标注」偏多，说明台账里的性质填写不规范，建议在台账中按 7 类标准校正（购房者优先权 / 工程款优先权 / 抵押债权 / 职工债权 / 税收债权 / 普通债权 / 劣后债权）。
- **已下线**：申报金额区间分布、债权种类统计/分布（按需求删除，接口也不再返回 `brackets` / `by_category`）。

## 流程说明

1. **上传**：`POST /api/projects/{id}/upload` 保存文件并同步解析，返回预填好的债权记录
2. **登记**：台账行「✎ 初审 / 编辑」→ 保存即自动登记（`PUT /api/claims/{id}`，名称为空则仍保持待登记）；取消登记 `POST /api/claims/{id}/unregister`
3. **AI 审查**：`POST /api/claims/{id}/ai-audit` 后台线程执行，前端轮询 `GET /api/claims/{id}/audit`
4. **人工复核**：`POST /api/claims/{id}/manual-audit` 保存审核金额与意见
5. **导出**：`GET /api/export/ledger?project_id=&fmt=xlsx|csv`、`/api/export/opinion/{claim_id}`、`/api/export/opinions?project_id=`

## 台账页怎么用（界面约定）

- **数据进出四件事集中在页面顶部**（标题区只留「❓ 使用指引」）：
  - **空项目**显示 4 张动作卡，各自带说明：🆕 **新增债权申报**（上传材料自动建档，也可把文件拖到卡片上）｜📥 **导入台账 Excel**（卡内含「下载导入模板」）｜🌐 **在线申报**（债权人自填、管理人拉取，卡上显示待导入条数徽标与提示）｜📊 **导出**（导出台账 Excel / 导出意见书 zip，并提示「只导其中几笔：先勾选行，再用批量条导出」）。
  - **有数据**时收成一行紧凑操作条：🆕新增债权申报 ｜ 📥导入台账 ｜ 📋模板 ｜ 🌐在线申报(徽标) ｜ 📊导出台账 ｜ 📄意见书 zip，下方一行显示待导入申报提示；整条操作条本身就是拖拽上传目标。
- **每行只显示「当前该做的一步」**主按钮：待登记→「✎ 初审 / 编辑」（**保存后自动登记为「已登记」**，不再有单独的「登记」按钮）、已登记未审查→「🤖 AI 审查」（点击即发起，无需跳页）、已登记且 AI 已完成→「✍️ 人工复核」、已复核→「📄 查看结果」；审查进行中显示禁用的「⏳ 审查中」。
- **取消登记**：行内「⋯ → ↩ 取消登记」，状态回到「待登记」（申报材料、AI 审查与人工复核记录全部保留）；已登记、已复核都可取消，已是待登记时接口返回 400。
- **初审/编辑弹窗的金额汇总**：申报总额＝申报本金＋利息＋其他，审核总额＝审核本金＋利息＋其他，两个总额框**只读、随分项实时汇总**，保存时后端也按分项重新汇总（分项全为 0 且原有总额时保留原总额，避免误清零）；原总额与分项之和不等时弹窗会给出橙色提示。
- **其余操作收在行内「⋯」菜单**：初审/编辑、审查工作台、人工复核、补充材料、材料预览、重新解析、删除该债权（危险操作不再直接暴露在按钮区）。
- **点整行**进入该债权的「债权审查工作台」（按钮、复选框、链接不受影响）。
- **顶部统计卡可点击筛选**：点「待登记/已登记/已复核」卡片即只看该类；工具栏的状态分段按钮与卡片联动。
- **高级筛选默认收起**（种类/性质/AI 审查状态/金额区间），有筛选生效时工具栏显示黄点提示，可随时「↺ 重置筛选」。
- **操作列固定在表格最右侧**，横向滚动时始终可见；默认只显示 8 列（编号·名称·性质·申报总额·**核减金额**·状态·AI审查·操作），其余列到「⚙️ 列设置」里开启（设置记忆在浏览器本地，键名 `ledger_cols_v2`）。
- **核减金额列** = 申报总额 − 审核总额，并附核减比例（未复核时显示「—」）；金额列右对齐等宽显示，便于纵向比对。
- **批量操作**：勾选若干行后表格上方出现批量条 —— 「✓ 批量登记」（缺名称的自动跳过并计入提示）、「🤖 批量 AI 审查」（并发发起 + 统一轮询，完成后汇总成功/失败笔数）、「📊 导出选中台账」「📄 导出选中意见书」（对应 `ids=` 参数，只导出选中债权，按传入顺序排列）、「🗑 批量删除」、「✕ 取消选择」。
- **台账 / 审查 双 Tab**：两个视图顶部共用一条 Tab 栏（`#/ledger?project=X` 与 `#/ledger?project=X&tab=audit`），切换即换视图、URL 可回溯，不用再回项目管理页绕行。
- **筛选标签**：已生效的搜索词、流程状态、种类、性质、AI 审查状态、金额区间会显示成标签，点标签上的 ✕ 单独移除某个条件，多条件时提供「清除全部」。
- **使用指引**：右上角「❓ 使用指引」弹窗按 6 步说明全流程（建档 → 登记 → AI 审查 → 人工复核 → 补充材料 → 导出）。
- 上传区（紧凑操作条 / 空项目时的「新增债权申报」卡）是**新增债权**入口（上传材料自动建档 PC-XXX）；给**已有债权**补材料请走该行「⋯ → 补充材料」。

## 后续扩展点（已预留接口）

- **OCR 精度提升**：当前用 RapidOCR（onnxruntime 版 PaddleOCR 模型，本地推理，约 10-60 秒/份扫描件）；扫描件识别效果受清晰度影响，可换 PaddleOCR 完整版或云 OCR 提升精度
- **多模型**：`llm.py` 支持任意 OpenAI 兼容接口（通义/智谱/本地 Ollama），改 `.env` 即可
- **鉴权**：多用户场景可在 `main.py` 增加登录与角色（登记员/复核员）
- **审计日志**：可加操作日志表记录登记/复核/导出的操作人

## 在线申报债权（使用说明）

1. **设置云端项目码**：项目管理 → 新建/编辑项目时填写「云端项目码」（须与云端 `CLOUD_PROJECT_CODES` 一致，如 `DEMO2026`）
2. **获取地址**：进入某项目台账 → 点「🌐 在线申报」→ 弹窗顶部显示**本项目云端申报地址**（自动带 project/case/debtor/manager 参数），点「复制链接」
3. **发给债权人**：债权人打开云端地址，填写债权信息，并在**「6 上传证据材料」证据目录**中逐项填写证据名称、上传对应证据材料（表格默认 **8 行 2 列**，点「＋ 添加一行」可增加行；每行可上传多个文件），提交后获得云申报号（C-xxx）
   - 证据材料按 **「证据名称-原文件名」** 上传（未填证据名称时保留原文件名），管理人收到的材料与证据目录一一对应；本地打包下载的 ZIP 按 `证据材料/序号 证据名称/文件名` 分目录
4. **拉取**：管理人在同一弹窗「云端配置」填写云端地址/令牌 → 保存 → 「⬇ 拉取云端申报」或「⬇ 拉取并导入台账」（幂等去重，云端已确认的不会重复拉取）
5. **导入台账**：拉取后的申报出现在「待导入申报」列表 → 点「🚀 更新在线申报」一键导入：自动生成债权编号 PC-XXX、材料文件入库、后台异步解析（OCR + 字段提取自动同步台账）
6. **同名查重**：台账已存在同名债权人时弹窗确认，可「继续导入（并存）」或「取消返回核对」

## 公网部署（阿里云接收暂存 → 本地拉取）

数据流向：**申报页（阿里云）→ 接收服务暂存 → 本地工具拉取 → 写入本地 SQLite**。

- 云端侧交付物在 [`cloud/`](cloud/README.md)：FastAPI 接收服务（校验/限流/暂存/管理接口）+ 部署脚本 + systemd 服务 + HTTPS 配置示例；
- 根目录 `债权申报.html` 为公网申报页（支持 `?project=&case=` 参数，云端提交失败自动降级本地打包）；第 6 节为**证据目录表格**（证据名称 + 点击上传证据材料，默认 8 行 2 列，可添加行），部署时需同步到 `cloud/receiver/static/index.html`；
- 实施步骤：安全组放行端口 → 上传 `cloud/` → `sudo bash deploy.sh 8080` → 生成申报链接；详见 `cloud/README.md`；
- **本地侧已实现 `cloud_sync` 模块**（`app/routers/cloud_sync.py`）：台账「🌐 在线申报」弹窗内配置云端地址/令牌 → 拉取（幂等去重）→ 写入 `online_claims` 表（`cloud_claim_id` 防重复）→ 「拉取并导入」直接进台账（编号/材料入库/OCR/同名查重）；接口：`/api/cloud-sync/config|test|pull|pull-and-import`。

## 分享给其他人（局域网协同）

服务默认监听 `0.0.0.0`（局域网可访问），分享步骤：

1. **启动服务**：`cd backend && python run_verified.py`（或双击 restart.bat）
2. **放行防火墙**：右键**以管理员身份运行** `share_lan.bat`（自动添加端口 8000-8020 入站规则并显示本机 IP）
3. **把地址发给同事**：`http://本机IP:端口`（端口看启动窗口，8000 被占用时自动 8001…），同事需与你在**同一 WiFi/局域网**
4. 同事访问即可协同管理（台账/审查/导出/在线申报全部可用）

> ⚠️ 注意：当前版本**无登录鉴权**，局域网内任何人拿到地址都可操作全部数据；仅限可信内网使用。如需公网访问或访问保护（登录口令/申报邀请码），可后续扩展。
